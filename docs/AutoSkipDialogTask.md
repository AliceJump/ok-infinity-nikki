# 剧情跳过与选项记忆

`AutoSkipDialogTask` 是默认关闭的触发任务，每 0.3 秒检查一帧。选项选择不再点击聊天气泡，而是使用键盘 `S` 向下移动、`F` 确认。每次**新出现**的选项菜单都假定游戏默认高亮第一项（索引 0）；目标为第 `i` 项时发送 `i` 次 `S`，最后发送一次 `F`。不使用 `W` 回退，也不改变全局 `PostMessage` 输入配置。

- 必须同时检测到 `dialog_icon` 和 `skip_choose`，再识别右侧 `chat_icon`，用每行文本带长度和选项数匹配历史指纹。未能可靠测量文字时不操作。
- 同一菜单一次只发送一个按键，每轮发送前后留存截图。按键后先获取一张新截图；`S` 后以及下一轮操作前再次确认对话菜单和文字指纹仍匹配，异常立即停机而不是盲目继续发送 `F`。
- `F` 后，只有连续两帧不再检测到选项菜单，才认为本次选择成功并推进该指纹的下次选择位置。如果菜单持续存在最多再检查 5 帧，停止该菜单所有自动操作，不重复尝试或推进记忆。
- 失败会记录警告与 `dialog_ws_failed` 截图，直到菜单连续两帧消失才解锁；关闭/重开任务会重置临时状态。`dialog_ws_before_*`、`dialog_ws_after_*` 和 `dialog_ws_confirmed` 截图可帮助对照键盘输入和游戏界面实际响应。
- 普通剧情没有 W/S 提示但有 `skip_f` 时，沿用原有一次 `F` 推进逻辑；孤立的提示和任务道具弹窗仍不处理。
- 菜单指纹只保留在内存里；选项数量和归一化文本长度近似匹配时轮流尝试不同选项。长度相近的不同菜单仍可能碰撞。

**适用前提和限制**：这是按“新菜单默认选中第一项”假设实现的输入方式。日志和模拟截图无法证明游戏确实移动了高亮；截图检查只验证菜单持续存在和 `F` 后退出，不代表 `S` 的每次高亮移动都已得到语义确认。游戏在键盘焦点丢失、默认项不是第一项或不接受后台 W/S/F 时，仍可能出现选择错误或停机。需要游戏实机验证。目标截图、模板资源和子模块 gitlink 未在本次 PR 中改变。
